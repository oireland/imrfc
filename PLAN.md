# Build plan

Vertical slices, built in order, each test-first (red → green → refactor). A slice is done when its tests pass, it works end-to-end in `pnpm dev`, and the user has reviewed it. Spec: [SPEC.md](SPEC.md).

- [x] **0. Scaffold** — Next.js (App Router, TS, pnpm); Tailwind + shadcn with the crest palette theme file (SPEC → Look and feel); Drizzle; Vitest with a PGlite test-database helper; Playwright; `docker-compose.yml` (Postgres + Mailpit); feature folder layout; one passing test of each kind.
- [x] **1. Sign-in & approval** — Better Auth (Google + magic link via pluggable mail sender); Pending → Approved; `ADMIN_EMAILS` bootstrap; Roles; route guards; Admin pending list + badge.
- [x] **2. Users admin** — change Roles; block/unblock (sessions revoked). Duty/equipment side-effects come in slice 10.
- [x] **3. Locations** — Committee CRUD, Venue/Store flags, archive. (Later: Venues became free text on Events and Locations became Stores only.)
- [x] **4. Equipment Units** — Committee CRUD, Home, Equipment Status, Condition Note.
- [x] **5. Whereabouts & Moves** — ad-hoc Moves, Movement Log, Equipment view grouped by Whereabouts, Equipment Unit detail.
- [x] **6. Events** — Training/Match/Social with type-specific details, Teams (seeded), Upcoming/Past, Event detail with maps link, Cancel.
- [x] **7. Series** — create with end date → Occurrences; edit "this one" / "this and future"; extend; cancel an Occurrence.
- [x] **8. Checklists** — Default Checklist per Event Type, Series and Event overrides, resolution order.
- [x] **9. Duties** — Claim/Assign To Duty → From Duty follows; hand on; Destination defaulting to Home.
- [x] **10. Confirm** — Confirm → Move; Unconfirmed after Event end; Cancelled Events void Duties; Blocking side-effects on Duties and held Equipment.
- [x] **11. Home screen** — my Duties, next Events, Equipment I Hold.
- [x] **12. Clashes** — the four warnings on Event and Equipment Unit views.
- [x] **13. Duty Summary** — WhatsApp copy button.
- [x] **14. Calendar Feed** — Feed Token, ICS with my Duties, reset, dead for Blocked Users.
- [x] **15. Design pass** — sweep every screen: replace raw HTML controls with shadcn/ui components, apply the crest palette theme tokens (SPEC → Look and feel), consistent mobile-first layout, light/dark check.
- [x] **15a. Clubhouse redesign** — warm light/dark theme with the crest as theme menu (saved per User); no app name; Home with 2-up Duty cards and What’s coming up (month Calendar with readable Events and tap-a-day quick add, Agenda); Events uses the same view; add Equipment Units and Events from their own pages; toasts on create; back links; clearer Equipment view.
- [x] **16. Quantity & split Whereabouts** — Quantity on Equipment Units (default 1, hidden at 1, raise/lower logged); Whereabouts as portions with counts; ad-hoc Moves with a count and a source; Equipment view shows split units in each group; migrate existing units to one portion.
- [x] **17. Checklist counts & Clashes by total** — Checklist lines ask for a count (default "all", capped at Quantity) at every level; Clashes fire only when overlapping/back-to-back Events need more than the Quantity; counts in Who's bringing what and the Duty Summary.
- [x] **18. Shared Duties** — several Users per Duty (Claim joins, Assign multi-select, leave / hand on your own place, From follows To); Confirm by any of them; confirm sheet asks where from (split unit) and who has how many (several Users, count > 1); Unconfirmed per portion; heads-ups, Blocking, Home, Duty Summary and Calendar Feed copy for several Users.
- [x] **18b. Onboarding** — a dismissible modal for a new User (blank name or no Preferred Position): name and Preferred Position (from the Players list, ahead of slice 20), a "what's in each tab" guide. "Not now" delays it for this browser tab; it reappears in a new tab or session until completed.
- [x] **19. Tabs** — drop the Events tab; "See all" from What's coming up on Home to Events; Members get Home · Equipment · Profile, Committee add Players (placeholder until 20) and Admin.
- [x] **20. Players & Positions** — `players` feature: Playing (default on; switched off by the User or Committee), Preferred and Other Positions; Playing section in Profile; Players tab (position order, name search, Not playing section); Player page with Positions and the duty record (upcoming, season count, last 5). Clubhouse mock-up of the list and Player page first.
- [x] **20a. Availability replies** — `availability` feature: Available (optional note) / Not available (Reason required) / No reply for Training and Matches; one reply covers every Match that day; change until start; Committee reply for a Player ("set by"); Reasons for Committee and the Player only; Availability card on Event detail (counts, three tabs, theme colours); Share button, sign-in returns to the page, title-and-date link preview.
- [x] **20b. Announce & Nudge** — Announce once per Event (whole day for Matches) with optional Reply By and "late"; Nudge all with No reply or chosen ones, "nudged 2h ago"; emails linking to the Event; Copy chase message.
- [x] **20c. Availability on Home & Player page** — "Can you make it?" card on Home for announced Events with no reply, answered inline; season Availability record on the Player page.
- [x] **20c+. Events tab** — Events back in the bottom tabs; Event Type filter on Events; Calendar/Agenda and the filter in the URL for bookmarking; reply (I'm in / I'm out) or see your reply on each Training and Match in the Agenda and under the Calendar's selected day; Home shares the same view and filter. Dev-only `/api/dev/sign-in` (DEV_SIGN_IN=1) so e2e specs sign in without Mailpit and run in parallel.
- [x] **20d. Selection board** — `selection` feature (SPEC → Selection): one shared board per match day with a pitch per Match, Shirts 1–23 plus Add a shirt, coloured by Availability; tap a Shirt for everyone sorted by Position (Preferred, Other, paired cover, rest) with out-of-position flag; Guests; move between pitches; swap; drag on wide screens; per-Shirt saves with ~5s refresh and "Tom moved this"; read-only when past or Cancelled; Committee only, from Event detail. Clubhouse mock-up of the board (phone and wide) first.
- [x] **20e. Team Sheet** — fields from the Event (overridable on the sheet), Schedule line, Sheet Defaults per Team, Match Day Roles, what's missing, live preview, PDF via `@react-pdf/renderer`. Mock-up of the sheet screen first.
- [x] **20f. Name the team** — Name the team per Match and Send changes (only the affected told, dropped included); Team card first under the details on Event detail for everyone, with the PDF; Home "You're playing" card; email + push in the background with "didn't reach"; Committee push when a picked Player replies Not available after naming. Mock-up of the Team card and Home card first.
- [x] **20g. Event form** — Event type first; derived titles ("Training @ Venue", "Team vs Opponent"); a Match has exactly one Team and Kick-off, Meet Time and Transport Meet Time that can each be TBC; Training and Social have no Team; tapping a calendar day only scrolls to its list. CSV import follows.
- [x] **20h. Message on WhatsApp** — `contact` feature (SPEC → Contact): optional Mobile number (`07…` or `+…`, E.164 via `libphonenumber-js`, Committee and self only, wiped on deletion) on Profile, the Player page and Onboarding (Playing on and no number re-opens the modal); Player page WhatsApp button; Message on WhatsApp sheet on the Availability card (No reply list, "No number" greyed, prefilled `wa.me` link in a new tab); "Sent it?" on return and Sent ✓ record Messaged, shown beside "nudged".
- [ ] **20i. Players list search & filter** — Players tab searches as you type (debounced, no Enter; query in the URL), lists Players alphabetically by name by default, and filters by Position (Preferred or Other Position) alongside the name search; the Not playing section follows the same search and filter. Position order stays available as a sort.
- [x] **20j. Time away** — `players` feature (SPEC → Time away): Away periods (from, until, required Reason; edit, I'm back, remove if future or mistaken, history), on Profile and the Player page (Committee set one "set by"), Home Away card (joins the health-card stack, see slice 21), Players list "Away until…" and Away chip; Not chased for Away in `availability` (Announce, Nudge, WhatsApp sheet, Home, morning-of push skip them; Away / Injured group on the Availability card; a reply wins); Committee push when Away starts within 14 days. Mock-up shared with slice 21.
- [x] **21. Injuries** — Clubhouse mock-up done (published artifact "Injuries and Away Mock-up", approved: stacked Home cards, six phone screens, light and dark; https://claude.ai/artifact/J9PK9MoPZsY2y5EfKTud9C); build from it (Profile Playing section, report form, Update sheet, Home cards, Players list rows, Player page; phone, light and dark). `injuries` feature: statuses Out · Training only · Playing through it · Cleared, Needs physio + note, Expected Return with Not sure yet and the "Still expecting…?" prompt, one Update sheet (any status to any, progress note), history with who/when, Logged by mistake; Fitness (worst open Injury) on the list with the summary line, Injured chip and New dot, check-in flags, Home health-card stack (my own open Injuries, most urgent first, collapsed with a "+N more" badge, tap to expand), privacy line; Fitness extends Not chased (Training only for Matches, Out for both); Committee push on a new Injury or a worse status ("Jo King is now Out", opens the Player page).
- [ ] **22. Concussion timeline** — Concussion flag, Symptom-free Date, Earliest contact training / Earliest Match, GRAS stages, NHS 111 / GP prompts, Committee-only Clear.
- [x] **23. Physio list** — "Copy physio list" on the Players page (whole club) and on Matches (the picked team only, not Training): open Injuries with Needs physio ticked, each with area and note. Text only.
- [x] **24. PWA & Push** — manifest, icons (generated from `docs/brand/crest.png`), iOS home-screen meta, service worker; `push` feature (subscriptions, morning-of reminders for Duties/Available replies on today's Events, a push alongside Announce/Nudge); Notifications toggle on Profile; daily Vercel Cron. See [ADR 0004](docs/adr/0004-web-push-over-third-party-and-daily-cron-drift.md).
