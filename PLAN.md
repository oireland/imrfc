# Build plan

Vertical slices, built in order, each test-first (red → green → refactor). A slice is done when its tests pass, it works end-to-end in `pnpm dev`, and the user has reviewed it. Spec: [SPEC.md](SPEC.md).

## First: harden the equipment ledger

Do these before the remaining v1 slices below. The invariant: for every Equipment Unit, the counts across its portions always equal its Quantity, and every change to Whereabouts can be explained by the Movement Log. Stay inside `equipment` and `duties`. No new features and no UI polish here.

Already done: CI (#30), the clash sweep-line (#31), back-to-back Clashes and Event foreign keys (#32), the ledger rules enforced in Postgres (#33), the flaky contrast check (#34), the unit lock proven on real Postgres (#36), property-based tests (#37; replay still waits for L4–L5), Confirm under concurrency (L1, #38), the query-count re-measure (L2, #39), no writes on page loads (L3, #40) the Movement Log as source of truth (L4), old data on the ledger (L5), the ledger ADR (L6) and the smaller fixes (L7).

- [x] **L1. Make Confirm safe under concurrency** — `confirmDuty` checks `confirmedAt` before its transaction, so two simultaneous Confirms can both record a Move. Set it first inside the transaction (`update duty set confirmed_at = … where confirmed_at is null returning`); no row back means this Confirm lost the race. `recordConfirmMove` loads portions and picks sources before `recordSplitMove` takes the lock, so stale sources can fail a valid Confirm: take the unit lock first. `withUnitLock` uses `FOR UPDATE`, which also blocks foreign-key checks from other tables: use `FOR NO KEY UPDATE`. **Done when:** two concurrent Confirms of one Duty on real Postgres (`*.pg.test.ts`) record exactly one Move, and inserting a Duty for a locked unit doesn't wait.
- [x] **L2. Re-measure query counts** — `docs/performance-report.md` measured 1,655 queries for Home in September, and there's no verified "after" number. Re-run the same seeded measurement for each page in that report and add a regression test that caps Home's queries. **Done when:** the new counts are recorded and the cap is enforced by a test. _Done in #39: Home 1,655 → 27 queries, Event detail 1,088 → 39, Equipment detail 1,076 → 13, Equipment 576 → 5, Events 541 → 13; budgets in `src/app/(app)/query-budget.test.tsx`._
- [x] **L3. Stop writing during page loads** — `ensureDuties` runs on Event detail, and `markUnconfirmedOnce` runs on Home and Equipment. Move them to mutations or the cron job, or derive the state on read. Any write that stays on a page load needs its reason recorded in an ADR. **Done when:** rendering those pages writes nothing, or the ADR explains the exception. _Done: Event detail derives blank Duties on read (`listEventDuties`) and `actOnEventDuty` creates the rows when someone acts; `markUnconfirmed` stays on Home and Equipment as the one recorded exception (ADR 0006); `query-budget.test.tsx` asserts no page writes._
- [x] **L4. Make the Movement Log the source of truth** — every change to Whereabouts appends a ledger entry. `equipment_portion` becomes a rebuildable view of the ledger, updated in the same transaction so reads stay fast. Today `savePortions` deletes and re-inserts the current state, and `movement_log_entry` is kept separately. **Done when:** replaying the ledger exactly reproduces the portions of every Equipment Unit. _Done: replay rules in `equipment/ledger.ts`; every write goes through `appendToLedger`, which logs and updates the portions in one transaction; `replayWhereabouts` rebuilds a unit from its log, checked after every step of the property tests. To make that work it took in most of L5's list: `added`, `bought`, `lost` and `unconfirmed` entry kinds, Unconfirmed as a `to_type`, last-seen Event ids at both ends (no foreign key), a source for every lost and whole-Quantity entry, a `seq` column for order (`created_at` is the same within a transaction), and a nullable user for Unconfirmed and for added stock nobody knows the source of. Old "Bought N"/"Lost N" notes became their own kinds. Replay matches for every unit created since; units from before still need L5._
- [x] **L5. Bring old data onto the ledger** — units created before L4 have no `added` entry, Unconfirmed changes before L4 weren't logged, and old `lost` entries may not say where from, so their log doesn't replay to their portions. Migrate them with opening-balance `added` entries (no user) so that replay gives today's portions — either worked back from today's portions through the old log, or with replay starting from a balance taken at migration time. The ADR (L6) records which. Also:
  - `movement_log_entry.created_at` has no time zone, but `duty.confirmed_at` does, and `hasMoveSince` compares the two. Make it `timestamptz` first.

  **Done when:** the migration runs on seeded data, and replay matches for every Equipment Unit (a test over `src/test/season.ts` data, plus a check of the dev database). _Done: migration 0037 takes the "balance at migration time" route, not working back through the old log (L6's ADR should say so): every unit gets one `opening` entry per Portion (no user), and replay starts at the latest run of opening entries, ignoring older history (kept for the history page). `created_at` is now `timestamptz` (old values read as UTC). Tested in `src/db/ledger-opening-balances.test.ts`; the dev database matches for all 8 units._
- [x] **L6. Ledger ADR** — record the design and the alternatives rejected (e.g. full event sourcing with no portions table, and why ledger entries have no Event foreign key). **Done when:** the ADR is in `docs/adr/`. _Done: ADR 0007._
- [x] **L7. Smaller fixes** _Done: the confirm sheet offers "Tom has it from Sam" (`handedOnSources`); the boundary test scans all of `src`, features export `client.ts` for client components, and a cycle check was added; `createTestDb` migrates its template once (the `migrate` helper is gone); SPEC says ~10s, Sheet Default is out of CONTEXT, ADR 0002 no longer lists features; CI has an `e2e` job (Postgres + Mailpit services)._
  - **Handed-on From Duty:** when Tom takes over from Sam, Tom's Confirm is correctly refused, but "What's being moved doesn't add up" gives no next step. Offer "Tom has it from Sam" in the confirm sheet.
  - **Boundary test:** it only scans `src/features`, and nine imports elsewhere reach into feature internals. Add a `client.ts` entry point for code that client components need, scan all of `src`, and add a cycle check.
  - **Test speed:** `src/test/db.ts` clones an empty template, so each database test replays every migration. Migrate the template once.
  - **Docs:** SPEC says the board polls every ~5s, but the code and ADR 0005 say 10s. CONTEXT still defines Sheet Default. ADR 0002 lists only six features.
  - **Playwright in CI:** it only runs locally today.

If L4–L5 overrun, they're the ones to cut.
